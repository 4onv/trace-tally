## Primary project sources

The following project pages were reviewed on November 1. Their current descriptions help interpret the historical theme; they are not historical growth measurements.

- [claude-mem](https://github.com/thedotmack/claude-mem) captures agent-session activity and makes relevant context available across sessions. Its privacy controls show that retaining and sharing agent data is an explicit design concern.
- [Lightpanda](https://github.com/lightpanda-io/browser) targets browser automation and AI workloads. It represents demand for the tools around agent execution.

The inference for TraceTally is practical: people changing their agent workflow need a small way to compare what happened, including when they cannot share the work's content.

## Selected scope

TraceTally v0.1 compares tool categories, observed outcomes, and recorded durations. It accepts an explicit Claude JSONL file or a neutral event stream, then writes portable JSON and HTML without raw transcript content. It uses no model API and does not execute the agent's commands.

The proposed adoption story is a readable before/after report someone can attach to a workflow discussion without embedding prompts or source code. The implementation is original, but neither the research nor this feature set establishes an unoccupied market.

The demo uses synthetic traces. Its numbers illustrate the interface, not a benchmark of a real agent. Fewer calls, fewer reported errors, or shorter recorded intervals do not by themselves prove that an agent did better work. Metadata can still reveal activity and deserves review before sharing.
